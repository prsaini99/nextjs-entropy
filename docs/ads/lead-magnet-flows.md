## Tool 1 — Build-vs-Buy Calculator (recommended v1)

**Promise:** "See what your marketing stack costs to rent — and what it would
cost to own."

### Flow

```
STEP 0 · Land on /stack-audit
   H1: "What is your marketing stack actually costing you?"
   Sub: "Pick your tools. See the 3-year rent-vs-own math. Takes 60 seconds."
   No form. No email ask. One button: [Start the audit →]
   → event: magnet_start

STEP 1 · Pick your tools  (single screen, grouped checklist)
   Categories: Email/Automation · CRM · Analytics · Ads · Chat · Social · Commerce
   Each tool a card: logo + name + "from ₹X/mo" hint
   "+ Add a tool we didn't list" free-text row
   Live counter in corner: "7 tools selected · est. ₹3.2–5.1 L/yr" (updates as
   they click — the number moving IS the hook)
   → event: magnet_tools_selected {count}

STEP 2 · Tune the assumptions  (one screen, 3 sliders/inputs)
   - Contacts / subscribers  (drives Klaviyo/Mailchimp/HubSpot tiers)
   - Team seats              (drives CRM/analytics tiers)
   - Monthly ad spend        (drives % -of-spend tools)
   Numbers update live. All assumptions visible: "HubSpot Starter est.
   ₹1,600/seat/mo — edit if yours differs."
   → event: magnet_adjust  (strongest intent signal — they're modelling
     their own case)

STEP 3 · Results  (ungated — value lands BEFORE the ask)
   ┌────────────────────────────────────────────┐
   │  Renting: ₹4.2–6.8 Lakh / year             │
   │  3-year cost: ₹13–20 Lakh — and rising     │
   │  with your list.                           │
   │                                            │
   │  Owning the equivalent: one build,         │
   │  typically less than a year of licence.    │
   │  Live in 2–3 weeks per project.            │
   ├────────────────────────────────────────────┤
   │  Per-tool table: tool · tier · ₹/yr ·      │
   │  keep / replace / build candidate          │
   └────────────────────────────────────────────┘
   The keep/replace/build column is the credibility move — we honestly mark
   cheap tools "keep" (GA4: keep, it's free) instead of claiming everything
   should be rebuilt.
   → event: magnet_results_viewed

STEP 4 · Email gate — for the artifact, not the numbers
   "Get this as a branded PDF + a human review of what we'd build first"
   [work email] [Send my audit →]
   → event: magnet_email_submit → POSTs to /api/contact with
     lead_source: 'stack-audit', full tool list + assumptions in
     projectSummary, plus UTM + gclid (already wired)

STEP 5 · Follow-up (human)
   Lead lands in Supabase with their full stack in the record — your team
   opens the call already knowing their tools, spend and list size.
   That's a qualified-lead dossier, not a form fill.
```

**Build pieces:** one page, a `stackPricing.js` data file (tool → tier → ₹
bands), pure client-side math, 5 events, reuse `/api/contact`.
**Effort:** days. **Risk:** price table staleness — review quarterly.

## Tool 2 — Stack Scanner (v2 upgrade of the same page)

Same flow with Step 1 replaced by detection:

```
STEP 1a · Paste URL → [Scan my site]
   → event: magnet_scan_start
STEP 1b · Server fetches homepage, matches script signatures (~5s, progress UI:
   "Checking analytics… ads pixels… automation…")
   → event: magnet_scan_complete {tools_found}
STEP 1c · Findings pre-fill the SAME checklist from Tool 1:
   "We found 6 tools. Loading tags via GTM? We can only see the container from
   outside — tick anything we missed."
   User corrects → continues into Step 2 (assumptions) exactly as Tool 1.
```

Everything downstream is identical — which is why shipping Tool 1 first is
free progress: the scanner only replaces the input method. Needs the SSRF
hardening from `lead-magnet-plan.md` (scheme allowlist, private-IP block,
redirect caps, timeouts, rate limit).

## Tool 3 — Branded PDF export (byproduct, not a magnet)

Not a standalone flow. Step 4's "branded PDF" is generated from the calculator
results — and generating it with your Proposal Maker pipeline turns the
deliverable itself into a demo of another product ("this PDF was generated by
the proposal engine we sell"). One line in the footer says exactly that.

## Tool 4 — Free AI Ad Score (sales tool, not site magnet)

Keep off the main funnel (compute cost per lead, zero search demand for the
category). Flow if/when used for outbound:

```
1. Prospect uploads one video ad (≤60s) + email — gated UP FRONT (compute
   costs money; this is the one tool where gate-first is correct)
2. Queue → TRIBE pipeline → email "your score is ready" link
3. Results page: Hook/Attention/CTA indices + the per-second curve, next to
   an anonymised benchmark ad
4. CTA: "Score a batch before your next campaign → talk to us"
```

Use for: LinkedIn outreach to performance marketers, agency pitches. Not `/stack-audit`.
